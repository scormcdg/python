Le bouton « Envoyer mes résultats » des séries, la base Neon, les rôles, les évaluations et le viewer « Résultats dans Neon ». Toutes les commandes SQL se tapent dans l'éditeur SQL de la console Neon.

Cette page est publique. Les mots de passe, adresses Neon et clés ci-dessous sont des exemples à remplacer. Ne publiez jamais les vrais sur GitHub : ils vont seulement dans les paquets SCORM, dans Moodle.

Le principe

Quand un élève clique sur « Envoyer mes résultats », la série relance la vérification de chaque exercice noté avec son code actuel, puis ajoute une ligne dans une table de Neon, colonne data (JSON) :

{ "serie": "serie05", "titre": "Série 05 – Dialoguer avec print et input",
  "eleve_chiffre": "k3Vb9…Qw==", "date": "…", "python": "pyodide",
  "exercices": [ { "id": "ex1", "titre": "Exercice 1", "code": "…", "tests": [1, 1, 0, 1] }, … ] }
  • tests : une valeur par vérification de l'exercice, dans l'ordre du fichier d'exercices (1 = réussie, 0 = ratée).
  • eleve_chiffre : le login Moodle et le nom (« Nom, Prénom ») de l'élève, chiffrés. Seul le viewer peut les lire.
  • date : heure de l'ordinateur de l'élève, falsifiable. L'heure qui compte est la colonne created_at, mise par le serveur.

Le viewer « Résultats dans Neon » (paquet SCORM caché aux élèves) lit les tables, déchiffre les noms et affiche un tableau élève × exercice.

eval_…une évaluation, supprimé après—ajouter

Chaque rôle a son propre mot de passe, donc sa propre adresse de connexion (le « code Neon ») :

postgresql://serie_eleve:MOTDEPASSE@ep-xxxx-pooler.c-3.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require
             └─ rôle ──┘ └─ mot ─┘ └───────────────── serveur et base (toujours les mêmes) ─────────────────┘
                         de passe

Où sont les réglages

Dans chaque série : serie.js

cleclé publique qui chiffre le login et le nom ; la même dans toutes les séries et évaluations

Dans le viewer : reglages.js

Le viewer doit toujours être caché aux élèves dans Moodle : il contient la clé privée et l'adresse qui lit tous les résultats.

Mise en place (une seule fois)

1. Les tables et l'heure du serveur

CREATE TABLE resultats_series (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  data jsonb NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);
CREATE TABLE resultats_exam (
  id bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  data jsonb NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now()
);

-- l'heure d'enregistrement est toujours celle du serveur, quoi qu'on envoie
CREATE OR REPLACE FUNCTION date_serveur() RETURNS trigger AS $$
BEGIN NEW.created_at := now(); RETURN NEW; END $$ LANGUAGE plpgsql;

CREATE TRIGGER date_serveur BEFORE INSERT OR UPDATE ON resultats_series
  FOR EACH ROW EXECUTE FUNCTION date_serveur();
CREATE TRIGGER date_serveur BEFORE INSERT OR UPDATE ON resultats_exam
  FOR EACH ROW EXECUTE FUNCTION date_serveur();

2. Les rôles des séries et du viewer

CREATE ROLE serie_eleve WITH LOGIN PASSWORD 'MOTDEPASSE1';
GRANT INSERT ON resultats_series TO serie_eleve;

CREATE ROLE prof_lecture WITH LOGIN PASSWORD 'MOTDEPASSE2';
GRANT SELECT ON resultats_series, resultats_exam TO prof_lecture;
  • Créez les rôles en SQL, pas avec le bouton « Roles » de la console Neon : les rôles créés par la console reçoivent beaucoup de droits (lire et modifier toutes les tables).
  • Mots de passe : longs (30 caractères), seulement des lettres et des chiffres, pour ne pas avoir à les encoder dans l'adresse.
  • L'éditeur SQL de la console vous connecte avec le rôle propriétaire de la base (souvent neondb_owner) : pas de mot de passe à taper.

Pour tirer un mot de passe au hasard, collez ceci dans la console du navigateur (F12, onglet Console) :

Array.from(crypto.getRandomValues(new Uint8Array(32)), b => "ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789"[b % 62]).join("")

3. Les adresses dans les paquets

  • serie.js de chaque série : neon: "postgresql://serie_eleve:MOTDEPASSE1@…" et table: "resultats_series".
  • reglages.js du viewer : neon: "postgresql://prof_lecture:MOTDEPASSE2@…".

Puis testez : « Envoyer mes résultats » dans une série doit afficher « Résultats envoyés à … ✓ », et la série doit apparaître dans le viewer avec votre nom.

Pour une évaluation

Les évaluations ont leur propre table, resultats_exam, et un rôle créé juste avant et supprimé juste après. Ainsi, l'adresse des séries (lisible par un élève qui fouille un paquet) ne permet pas d'écrire de faux résultats d'évaluation.

Avant

CREATE ROLE eval_nov WITH LOGIN PASSWORD 'NOUVEAUMOTDEPASSE';
GRANT INSERT ON resultats_exam TO eval_nov;

Dans le serie.js du paquet d'évaluation :

neon: "postgresql://eval_nov:NOUVEAUMOTDEPASSE@ep-xxxx-pooler.c-3.eu-central-1.aws.neon.tech/neondb?sslmode=require&channel_binding=require",
table: "resultats_exam",
cle: "…la même clé publique que les séries…",

Gardez l'activité cachée dans Moodle jusqu'au début de l'évaluation.

Pendant : Safe Exam Browser

Outils de développement interdits (réglage par défaut). Sites à autoriser, sinon la série ne se charge pas ou l'envoi échoue :

  • votre Moodle ;
  • scormcdg.github.io (fichiers communs) ;
  • cdn.jsdelivr.net (Python, Pyodide) ;
  • esm.sh (bibliothèque Neon) ;
  • *.neon.tech (la base).

Après

DROP OWNED BY eval_nov;   -- retire ses droits (sinon DROP ROLE refuse)
DROP ROLE eval_nov;

Cachez l'activité dans Moodle en même temps. Les résultats déjà envoyés restent dans resultats_exam et le viewer les affiche toujours. Pour repérer un envoi tardif : case « tous les envois » du viewer, colonne « Envoyé le » (heure du serveur).

Vérifier la configuration

Les triggers de l'heure

SELECT event_object_table, event_manipulation FROM information_schema.triggers
WHERE trigger_name = 'date_serveur';

Attendu : INSERT et UPDATE pour chacune des deux tables (une ligne par événement).

Les droits des rôles

SELECT grantee, table_name, privilege_type FROM information_schema.role_table_grants
WHERE table_name IN ('resultats_series', 'resultats_exam') AND grantee <> current_user
ORDER BY grantee, table_name;

Attendu : serie_eleve INSERT sur resultats_series ; prof_lecture SELECT sur les deux ; pendant une évaluation, eval_… INSERT sur resultats_exam. Rien d'autre.

Les rôles existants

SELECT rolname FROM pg_roles WHERE rolcanlogin ORDER BY 1;

Un ancien rôle d'évaluation encore présent : supprimez-le (voir Après).

Consulter les résultats en SQL

Le plus simple est le viewer. En SQL, les noms restent chiffrés : on voit les résultats, pas qui les a envoyés.

Nombre d'envois par série

SELECT data->>'serie' AS serie, count(*) AS envois, max(created_at) AS dernier
FROM resultats_series GROUP BY 1 ORDER BY 1;

Une ligne par envoi et par exercice

SELECT created_at, e->>'id' AS exo, e->>'tests' AS tests
FROM resultats_series, jsonb_array_elements(data->'exercices') AS e
WHERE data->>'serie' = 'serie05'
ORDER BY created_at;

Taux de réussite d'une vérification

-- vérification n° 3 (indice 2) de l'exercice ex2 de la série 05
SELECT round(100.0 * avg((e->'tests'->>2)::int)) AS pourcentage
FROM resultats_series, jsonb_array_elements(data->'exercices') AS e
WHERE data->>'serie' = 'serie05' AND e->>'id' = 'ex2';

Le visualiseur de tables de Neon affiche les tableaux JSON sur plusieurs lignes : c'est seulement l'affichage, la donnée est bien [1, 1, 0, 1].

Gérer les données et les rôles

Effacer des envois

-- les envois d'une série de test
DELETE FROM resultats_series WHERE data->>'serie' = 'test';

-- les envois d'une série avant une date
DELETE FROM resultats_series WHERE data->>'serie' = 'serie05' AND created_at < '2026-09-01';

-- tout vider (fin d'année), sans retour possible
TRUNCATE resultats_series;

Pour garder une trace avant d'effacer : « Télécharger en CSV » dans le viewer (avec les noms et le code).

Changer un mot de passe

ALTER ROLE serie_eleve WITH PASSWORD 'NOUVEAUMOTDEPASSE';

L'ancienne adresse cesse aussitôt de marcher : mettez la nouvelle dans le serie.js de toutes les séries et remplacez les paquets dans Moodle. À faire si une adresse a été publiée par erreur.

Supprimer un rôle

DROP OWNED BY nom_du_role;
DROP ROLE nom_du_role;

Retirer des droits à un rôle existant

REVOKE ALL ON resultats_series, resultats_exam FROM nom_du_role;

Les clés de chiffrement

Le login et le nom sont chiffrés avec RSA-OAEP (2048 bits, SHA-256) :

  • la clé publique (cle dans serie.js) chiffre seulement ; un élève qui la lit ne peut rien déchiffrer ;
  • la clé privée (cle_privee dans reglages.js du viewer) déchiffre.

Le chiffrement ajoute du hasard : le même élève donne un texte chiffré différent à chaque envoi. On ne peut donc pas retrouver un élève en chiffrant soi-même son login. Le viewer regroupe les envois après déchiffrement.

Gardez une copie de la clé privée hors de Moodle et de GitHub. Sans elle, les noms déjà envoyés ne peuvent plus être lus (les résultats et le code restent lisibles).

Créer une nouvelle paire de clés

Seulement si la clé privée a fuité ou est perdue. Collez ceci dans la console du navigateur (F12, onglet Console) :

(async () => {
  const k = await crypto.subtle.generateKey({ name: "RSA-OAEP", modulusLength: 2048,
    publicExponent: new Uint8Array([1, 0, 1]), hash: "SHA-256" }, true, ["encrypt", "decrypt"]);
  const b64 = async (f, c) => btoa(String.fromCharCode(...new Uint8Array(await crypto.subtle.exportKey(f, c))));
  console.log("cle (serie.js) :\n" + await b64("spki", k.publicKey));
  console.log("cle_privee (reglages.js) :\n" + await b64("pkcs8", k.privateKey));
})();

Mettez la nouvelle clé publique dans toutes les séries et la nouvelle clé privée dans le viewer. Les envois faits avec l'ancienne clé s'affichent alors « illisible (autre clé) » : gardez l'ancien viewer (ou l'ancienne clé) pour les relire.

Ce qui est protégé, ce qui ne l'est pas

RisqueProtection
Lire les noms des élèves dans la basechiffrés ; seul le viewer (clé privée) les lit
Lire ou modifier les envois des autres avec l'adresse d'une sérieimpossible : serie_eleve peut seulement ajouter
Écrire de faux résultats d'évaluationtable à part, rôle d'évaluation créé juste avant et supprimé juste après, Safe Exam Browser pendant

Envoyer de faux résultats de série, au nom d'un autre élèvepas protégé : l'envoi part du navigateur ; un élève aidé d'une IA peut le faire. Les séries servent au suivi, pas à une note.
