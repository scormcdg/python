Créer une nouvelle série SCORM

Faire une nouvelle série d'exercices Python à partir d'un zip de série existant, sans rien changer sur GitHub : on change seulement serie.js et le fichier d'exercices.

Le principe

Un zip de série ne contient que 5 fichiers. Tout le reste (moteur Python, tortue, éditeur, vérification, envoi des résultats, styles) est chargé depuis GitHub : https://scormcdg.github.io/python/script/pyodide/v1/ (Pyodide, le vrai Python, par défaut) ou https://scormcdg.github.io/python/script/v1/ (Skulpt, l'ancienne version, si serie.js le demande).

Fichier Rôle À changer pour une nouvelle série ?
data/serieXX.js les exercices : énoncés, code de départ, solutions, vérifications oui, c'est l'essentiel du travail
serie.js les réglages de la série : titre, identifiant, fichier d'exercices, version de Python, lien du tutoriel, envoi des résultats à Neon oui : le titre, l'identifiant et le nom du fichier d'exercices
index.html la page non
charger.js charge les fichiers communs depuis GitHub, d'après serie.js non
imsmanifest.xml la fiche SCORM lue par Moodle (titre générique « Série Python » : c'est le nom de l'activité dans Moodle qui s'affiche) non

Comme les fichiers communs sont sur GitHub, une correction faite sur GitHub s'applique à toutes les séries déjà dans Moodle. En contrepartie, il faut Internet pour que la série s'affiche.

Les réglages : serie.js

var SERIE_REGLAGES = {
  titre: "Série 06 – Les listes",      // en haut de la page et dans l'onglet du navigateur
  id: "serie06",                       // différent pour chaque série
  exercices: "data/serie06.js",        // le fichier d'exercices
  python: "pyodide",                   // facultatif : "pyodide" par défaut, "skulpt" pour l'ancienne version
  neon: "postgresql://serie_eleve:MOTDEPASSE@ep-xxxx-pooler…neon.tech/neondb?sslmode=require&channel_binding=require",
  table: "resultats_series",           // table de Neon où les résultats sont ajoutés
  cle: "MIIBIjANBgkqh…",               // clé publique qui chiffre le login et le nom de l'élève
  tutoriel: { texte: "Tutoriel tortue", lien: "https://scormcdg.github.io/python/tutoriels/tortue.html" }
};
RéglageRôle
titretitre affiché ; il remplace celui du fichier d'exercices
idsert à retrouver le travail des élèves : différent pour chaque série, et à ne plus changer une fois la série utilisée (sinon les élèves repartent de zéro)
exerciceschemin du fichier d'exercices dans le paquet
pythonfacultatif : Pyodide par défaut (le vrai Python) ; "skulpt" pour l'ancienne version. C'est la seule différence entre les deux versions d'une série
neoncode Neon du rôle qui ajoute les résultats ; null : pas de bouton « Envoyer mes résultats »
table"resultats_series" pour une série, "resultats_exam" pour une évaluation
cleclé publique de chiffrement, la même dans toutes les séries (sinon le viewer ne peut pas lire les noms)
tutoriellien en haut de la page ; null : pas de lien

Pour une nouvelle série, neon, table et cle se recopient tels quels depuis une série existante. Pour une évaluation, neon et table changent : voir le tutoriel Gérer les résultats dans Neon.

Le code Neon et la clé publique sont dans le paquet, visible seulement dans Moodle : ne mettez jamais un serie.js rempli sur GitHub.

Étapes

L'exemple fait une série 06 à partir de la série 05.

  1. Copier une série existante. Décompressez serie05-pyodide-scorm-leger.zip dans un nouveau dossier, par exemple serie06/. Prenez de préférence une série proche de celle que vous voulez faire : ses exercices serviront de modèles.
  2. Renommer le fichier d'exercices. data/serie05.js devient data/serie06.js.
  3. Modifier serie.js : titre, id ("serie06") et exercices ("data/serie06.js"). Le reste peut rester tel quel.
  4. Écrire les exercices dans data/serie06.js (voir la partie suivante). Mettez aussi en haut du fichier le même id et le même titre que dans serie.js : ce sont ceux de serie.js qui comptent, mais le fichier reste ainsi lisible seul.
  5. Tester en ouvrant index.html dans Firefox ou Chrome (double-clic). La page affiche « Mode test » : le travail est gardé dans le navigateur. Pour chaque exercice, collez la solution et cliquez sur Vérifier : tout doit être vert. Essayez aussi une ou deux mauvaises réponses. Hors de Moodle, « Envoyer mes résultats » demande un nom : l'envoi de test arrive vraiment dans Neon (effacez-le ensuite si besoin, voir le tutoriel Neon).

  6. Zipper le contenu du dossier, pas le dossier lui-même : imsmanifest.xml doit être à la racine du zip. Sur Linux, depuis le dossier serie06/ :

    zip -r ../serie06-scorm-leger.zip .

  7. Mettre dans Moodle : Ajouter une activité → Paquetage SCORM → déposer le zip, et donner un nom à l'activité. Pour corriger une série déjà en place, modifiez l'activité et remplacez le paquetage : les tentatives déjà faites restent normalement enregistrées (évitez de changer l'id de la série et les identifiants des exercices en cours d'année).

Pour passer une série de Skulpt à Pyodide (ou l'inverse) : changez seulement python dans serie.js, rezippez et remplacez le paquetage.

Si un élève ou vous-même ne voyez pas une correction faite sur GitHub, le navigateur a gardé l'ancienne version : Ctrl+F5.

Le fichier d'exercices

Le fichier data/serieXX.js décrit la série dans un objet SERIE : un id et un titre (remplacés par ceux de serie.js) et la liste exercices, dans l'ordre des onglets.

Champ Contenu
id identifiant court et unique dans la série : "exemple", "ex1", "ex2"… Ne plus le changer une fois la série utilisée
titre nom de l'onglet : "Exemple", "Exercice 1"…
note true : exercice noté, avec le bouton Vérifier. false : pas de vérification (pour un exemple)
figure true : affiche la « Figure attendue », dessinée avec la première solution
enonce le texte de l'énoncé, en HTML : <p>, <strong>, <code>, <ol><li>…
code le code de départ dans l'éditeur, entre accents graves `…` (voir les exemples) ou entre guillemets avec \n pour les retours à la ligne
solutions une ou plusieurs solutions justes ; le dessin de l'élève est comparé à celui des solutions
checks la liste des vérifications, affichées comme critères (partie suivante)
inputs facultatif : les réponses données à input() pendant la vérification, par exemple ["5", "100"]

En haut du fichier, deux aides servent dans les énoncés. CODE("…") affiche un bout de code sur ses propres lignes, et OPTS accepte un dessin tourné ou retourné comme celui de la solution.

Des exercices complets, testés, sont dans la partie Exemples complets.

Chaque exercice est entre { }, séparé du suivant par une virgule. Le plus simple est de copier un exercice existant de la série de départ et de le modifier.

Les vérifications

Chaque vérification de checks devient un critère dans la liste « Vérification » de l'exercice. Champs communs à toutes les vérifications :

ChampRôle
ididentifiant court, unique dans l'exercice : "def", "dessin"… (pas affiché ; il sert à ranger les résultats, par exemple dans l'envoi à Neon)
kindce qui est vérifié (tableau suivant)
labelle critère affiché à l'élève, tout le temps, en vert ou en rouge. Il est visible avant même de cliquer sur Vérifier : il sert aussi de consigne. Formulez-le comme ce qui doit être vrai, sans donner la solution : « Le programme pose deux questions avec input() », « moyenne() renvoie la bonne valeur ».
failfacultatif : l'explication affichée sous le critère, seulement s'il est raté. Pour les dessins, couleurs, affichages et appels, un message automatique précis est déjà donné (« … est trop grand », « … renvoie 12 au lieu de … ») : fail s'ajoute après. Pour "source" et "calls", il n'y a pas de message automatique : mettez toujours un fail.

Ce que voit l'élève, après avoir cliqué sur Vérifier :

✓ La fonction moyenne(a, b, c) existe, avec trois paramètres          ← label (réussi)
✓ moyenne() utilise return                                           ← label (réussi)
✗ moyenne() renvoie la bonne valeur (testé avec 12, 15, 9 ; …)       ← label (raté)
    moyenne(10, 15, 12) renvoie 12 au lieu de 12.333333333333334.    ← message automatique (+ fail s'il y en a un)

Les valeurs possibles de kind, et leurs champs :

kind Ce qui est vérifié Champs
"shape" le dessin, comparé à celui des solutions target : "<program>" (tout le programme) ou le nom d'une commande ; args : les valeurs de l'appel, par exemple [50] ; opts ; hint (facultatif) ; inputs (facultatif) ; ou, pour "<program>", cases : [{ inputs }, …] pour tester plusieurs jeux de réponses
"params" la commande est définie avec le bon nombre de paramètres name, count, example (par exemple "def carre(cote):")
"defined" la commande est définie name, fail (facultatif)
"calls" une commande en appelle une autre caller : nom d'une commande, "<main>" (programme principal) ou "<any>" (n'importe où) ; callee : la commande appelée ; fail
"source" le code contient un mot ou une forme, sans compter commentaires et textes re : expression régulière ; in (facultatif) : seulement dans cette commande ; fail
"output" ce qu'affiche print() re ; inputs ; ou cases : [{ inputs, re, attendu }, …] pour tester plusieurs jeux de réponses ; fail
"colors" les couleurs du trait et du remplissage, comparées à la solution inputs (facultatif) ; ou cases : [{ inputs }, …] pour tester plusieurs jeux de réponses ; fail
"call" une commande appelée avec des valeurs : ce qu'elle renvoie (return) et ce qu'elle affiche (print()), comparés à la solution name ; cases : [{ args }, …], par exemple [{ args: [12, 15, 9] }, { args: [10, 15, 12] }] ; returns dans un cas (facultatif) : la valeur attendue, au lieu de celle de la solution ; retour: false ou affichage: false (facultatif) : ne pas comparer ce qui est renvoyé, ou ce qui est affiché ; fail (facultatif)

Les options du dessin (opts)

  • rotate: true : le dessin peut être tourné.
  • mirror: true : le dessin peut être retourné (symétrique).
  • scale: true : la taille n'est pas vérifiée.
  • color: true : les couleurs des traits sont vérifiées.

OPTS, défini en haut du fichier, vaut { rotate: true, mirror: true } : c'est le choix habituel.

Les indices d'un dessin (hint)

Un texte s'ajoute au message quand le dessin ne correspond pas : hint: "Un carré a 4 côtés.". Pour un indice selon le problème : hint: { count: "…", size: "…", shape: "…" }. count sert s'il manque des traits ou s'il y en a trop, size si le dessin est trop grand ou trop petit, et shape si la forme est différente.

Avec input(), testez chaque dessin et chaque couleur avec deux jeux de réponses dans une seule vérification (cases) : avec un seul jeu, l'élève peut écrire la valeur testée directement dans le code. Avec cases, une erreur ne fait rater qu'une vérification, et le message indique les réponses qui posent problème.

Pour une commande avec paramètres, la règle "call" appelle la commande de l'élève et celle de la solution avec les mêmes valeurs, puis compare ce qu'elles renvoient et ce qu'elles affichent : il n'y a pas de résultat à écrire. Les nombres sont comparés à 0.000000001 près (4 et 4.0 sont égaux). L'affichage n'est comparé que si la solution affiche quelque chose. Le message dit ce qui ne va pas, par exemple « moyenne(10, 15, 12) renvoie 12 au lieu de 12.333333333333334. » ou « moyenne(12, 15, 9) ne renvoie rien : il manque return (print() affiche une valeur, mais ne la renvoie pas). ». Mettez la règle "params" avant : si le nombre de paramètres est faux, la commande n'est pas appelée.

Les vérifications sont faites dans l'ordre de la liste. Mettez d'abord les plus simples (la commande existe, la boucle est là), puis les dessins.

Exemples complets

Quatre exercices complets, testés tels quels avec la vérification. Pour chacun : la solution en Python, l'exercice tel qu'il s'écrit dans le fichier d'exercices, et ce que voit un élève qui fait une erreur typique. Copiez l'exercice le plus proche du vôtre, puis adaptez-le.

Dans ces exemples, le code de départ et les solutions sont écrits entre accents graves `…` : on écrit le Python tel quel, sur plusieurs lignes, avec son indentation. C'est plus lisible que "…\n…" (les anciennes séries) et ça marche pareil. Deux précautions entre accents graves : doubler les barres obliques inverses (\\n pour un \n dans le Python), et ne pas écrire ${.

1. Questions avec input(), dessin, couleur et message

L'élève demande une couleur et une taille, dessine un carré rempli, puis affiche un message. Chaque vérification qui dépend des réponses est testée avec deux jeux de réponses (cases) : une valeur écrite en dur dans le code ne passe pas. inputs donne les réponses utilisées pour la « Figure attendue » et pour les vérifications sans cases.

Solution

from turtle import *

couleur = input("Couleur ? ")
cote = int(input("Taille ? "))
color(couleur)
begin_fill()
for i in range(4):
    forward(cote)
    left(90)
end_fill()
print("Carré", couleur, "de côté", cote)

2. Une commande avec paramètre qui dessine

L'élève écrit carre(cote) et l'utilise. On vérifie la commande seule, appelée avec une autre valeur que dans le programme (target: "carre", args: [30]), puis le dessin de tout le programme. figure: true affiche la « Figure attendue », dessinée avec la solution.

Solution

from turtle import *

def carre(cote):
    for i in range(4):
        forward(cote)
        left(90)

carre(50)
forward(60)
carre(100)

3. Une fonction qui renvoie une valeur

Pas de tortue : la fonction moyenne(a, b, c) doit renvoyer un résultat. La vérification "call" appelle la fonction de l'élève et celle de la solution avec les mêmes valeurs et compare les résultats : aucune valeur attendue à écrire. Le jeu 10, 15, 12 (moyenne non entière) attrape la division entière //.

Solution

def moyenne(a, b, c):
    return (a + b + c) / 3


print(moyenne(12, 15, 9))

Pièges fréquents

Symptôme Cause Correction
Les exercices n'apparaissent pas (page vide, sans onglets) une erreur de syntaxe JavaScript dans data/serieXX.js : virgule oubliée entre deux exercices, guillemet non fermé, { ou [ en trop ouvrez la console du navigateur (F12, onglet Console) : elle indique la ligne fautive
Le texte s'arrête au milieu d'un énoncé un " dans un texte entre "…" écrivez \", par exemple "<code>print(\"Bonjour\")</code>", ou utilisez ' pour l'apostrophe
Le code de départ tient sur une seule ligne les retours à la ligne manquent écrivez \n à chaque fin de ligne, et 4 espaces pour l'indentation
Une règle source ne trouve jamais le mot dans re, la barre oblique s'écrit en double "\\bfor\\b" pour le mot for, "\\(" pour une parenthèse
Vérifier affiche « Solution de référence invalide » la solution elle-même plante, ou elle pose plus de questions input() que de réponses dans inputs exécutez la solution dans l'exercice et corrigez-la
La bonne réponse est refusée une vérification ne correspond pas à la solution (mauvaises valeurs dans args, texte différent dans re) collez la solution et cliquez sur Vérifier : tous les critères doivent être verts
Deux séries partagent le même travail en mode test même id en haut des deux fichiers d'exercices donnez à chaque série un id unique
Moodle refuse le zip le zip contient le dossier au lieu de son contenu imsmanifest.xml doit être à la racine : zippez depuis l'intérieur du dossier

Le message « L'exercice n'a pas pu se charger : le site qui contient les fichiers de l'exercice ne répond pas » veut dire autre chose : GitHub ne répond pas, ou exercices dans serie.js ne correspond pas au nom du fichier du dossier data.

Avant de mettre la série dans Moodle, faites ce contrôle pour chaque exercice :

  • la solution collée dans l'éditeur donne tous les critères en vert ;
  • une réponse fausse typique (valeur écrite en dur, boucle oubliée) est refusée avec un message compréhensible ;
  • aucun message d'échec ne donne la solution toute faite.
